# 0004：平台运行能力检测与连接前检查

日期：2026-10-26；状态：已实施，当前工作区待提交。

## 背景

DPAPI、ConPTY、串口和 mstsc 已迁入 Windows 平台项目。UI 仍默认本地功能均可用，缺少组件时只能启动后报错；串口枚举在构造任意协议编辑器时发生，枚举失败也可能影响网络会话编辑。

## 决策

- Application 定义 `IPlatformCapabilities`、能力标识及结构化可用状态/原因；`PlatformConnectionPolicy` 只为 Shell、Serial、RDP 查询对应能力，网络协议不查询本地能力。DPAPI 不作为连接远程桌面的前提，密码库的保护失败仍由原有端口处理，不降级加密。
- Windows 每次查询都重新检测：DPAPI 与 ConPTY 检查系统目录 DLL 的所需导出，RDP 检查启动器实际使用的系统 mstsc 路径；检测不启动进程、不打开设备、不处理秘密。探测 I/O/权限失败转为固定原因，UI 不展示原始异常或系统路径。
- Windows 串口运行支持不取决于当前设备列表。枚举为空和枚举失败分别提示，但都允许手动输入；设备存在、占用、权限和驱动实际可用性由连接操作确认。
- UI 编辑器保持全部协议可选，缺少支持时禁用连接并解释原因，保留仅保存；切换协议和重新激活窗口时刷新，点击连接时再次检查。现有配置不保存能力状态或改写协议字段。
- 连接入口在创建适配器、读取已保存 RDP 密码和启动客户端前检查能力，失败页提供重新检查。恢复后在原标签创建连接；RDP 的再次启动也检查能力。凭据从仍解锁的密码库重新读取，保留复制密码入口。替换 RDP 页面时释放页面所属的剪贴板计时器。
- 帮助菜单展示全部四项平台能力。能力“可用”仅说明运行前提；真实进程启动、设备访问、服务器认证和权限检查继续按原诊断处理。

## 影响与限制

没有增加依赖、持久化字段、锁文件变化或新操作系统支持。检测结果不是连接保证，也不能排除检查后系统支持发生变化；已有启动异常分类继续负责此类失败。能力只在当前 UI 入口与编辑器使用，直接调用适配器仍按其原有系统错误返回。

串口实机、真实 RDP 登录和受限 Windows 部署仍需专项验证。应用数据路径已由 ADR 0005 隔离；Windows 文件打开/保存对话框仍待迁入平台项目，Infrastructure 继续使用 Windows 目标。

## 复审条件

新增操作系统/能力、串口后端、外部桌面客户端，或路径服务改变系统组件定位方式时复审。必须验证网络不受本地能力限制、不可用会话可保存、恢复检查与再次启动、枚举失败可手输，以及检测不触发敏感或有副作用的操作。
