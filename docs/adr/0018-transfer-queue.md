# ADR 0018：文件标签内的串行传输队列

- 日期：2026-10-29
- 状态：已采纳

## 背景

P07 已有单任务进度与可等待关闭。P08 需要批量文件操作与逐项可见结果，同时保留 FTP/SFTP 的协议确认、覆盖、超时、取消及未知提交状态边界。

## 决策

- Application 提供独立队列策略，UI 用现有 IFileTransfer 执行；每个文件标签按加入顺序串行运行，只接受文件，不引入目录递归或新协议接口。队列以稳定任务 ID 管理五种状态，最多保留 500 项，只存内存。
- 加入与开始分开；覆盖逐项确认且默认拒绝。失败暂停等待项，继续与重试分别显式发起，均要求先核对结果；成功任务不会重放。
- 当前与等待任务分别取消。关闭取消整队并等待原操作及连接清理；已确认成功不因迟到取消改写状态。取消当前后可以继续下一等待项，整批停止应同时取消等待项。
- 系统多文件选择通过 IMultiFilePicker 端口适配；批量下载验证 Windows 文件名及清理后的碰撞。UI 进度必须回到界面线程，再检查操作编号及任务状态，避免迟到回调覆盖最终结果。

## 代价与验证

失败后的人工核对是必要步骤，队列无法从客户端失败推断远端是否提交，也不在重启后恢复。不同标签独立运行，不提供全局调度或跨客户端事务。复用传输契约检查，增加共享队列规则、选择器适配及真实 FileConnection 的 UI 检查；完整 UI 同时回归 P01–P07。操作及限制见[队列说明](../TRANSFER-QUEUE.md)。
