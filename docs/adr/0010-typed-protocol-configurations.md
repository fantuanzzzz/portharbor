# ADR 0010：协议运行配置类型化与旧数据兼容

日期：2026-10-27；状态：已采纳。

## 背景

原 `Session` 同时包含七种协议字段。直接改变序列化结构会影响已发布 JSON v1/v2、便携 INI、编辑器和凭据关联。

## 决策

保留 `Session` 作为兼容的编辑/存储 DTO；Domain 提供 `SessionMetadata`、`ConnectionProfile` 和 SSH、Telnet、RDP、FTP、SFTP、Serial、Shell 七种不可变配置。`Session.ProtocolConfiguration` 不参与 JSON 序列化，工厂投影后把对应类型传入适配器。SSH/SFTP 共享认证帮助方法接受明确参数，不让协议客户端读取全部会话字段。

网络和 Windows 终端适配器、FTP/SFTP 文件适配器、RDP 配置生成已消费类型化配置；连接生命周期仍持有会话副本用于校验和诊断标识。旧 ConPTY/SSH 帮助入口保留兼容包装。公共名称、分类、ID 和保存密码策略不混入协议运行配置，密码继续经已有凭据端口单独传入。

## 选项与影响

没有新增 schema 或批量改写旧配置。未启用协议的字段仍在 DTO 中保留，因此切换编辑协议不会丢字段；厂商适配器仅能访问对应协议字段。代价是 DTO 与运行配置有显式映射；新增字段必须同步映射和兼容检查。

七协议非默认字段分别通过旧 JSON/INI 往返，核验 ID、协议字段和未启用字段保持一致；既有 v1/v2 fixture、凭据关联与导入失败回滚继续验收。

## 复审条件

以后需要改变磁盘 schema 或彻底替换编辑模型时，再设计有备份和失败回滚的数据迁移；不能以删除旧字段代替迁移。
