# ADR 0019：SSH keyboard-interactive 认证与 UI 响应

- 日期：2026-10-30
- 状态：已采纳

## 背景

部分 SSH/SFTP 服务器不能只用密码或私钥完成登录，会要求一次性验证码、设备确认或多轮挑战。认证必须复用主机密钥校验和现有连接生命周期，不能将秘密复制到配置或日志。

## 决策

- Application 定义与厂商无关的挑战模型和同步响应委托；Infrastructure 使用 SSH.NET `KeyboardInteractiveAuthenticationMethod`，并在密码/私钥方法之后追加该方法。
- 每轮提示按服务器顺序传入 UI；`IsEchoed=false` 使用隐藏输入，`true` 使用普通输入。UI 回调在主窗口线程执行，任意一轮取消抛出专用取消异常并正常释放连接。
- SSH 终端和 SFTP 共用同一回调，不自动重试、不缓存响应、不写配置/日志/终端。主机密钥事件先完成原指纹确认，认证失败不能改变信任记录。
- 连接期限约束网络握手和通道建立；原生提示等待由用户控制，取消按钮是结束等待的明确操作。连接结束统一清理 SSH client、Shell/SFTP 通道和私钥资源。

## 代价与验证

同步 UI 回调会在认证提示期间占用连接线程，避免把服务器挑战拆成后台状态机；用户必须完成或取消当前提示。服务器若发送异常数量的响应，客户端按取消处理。Paramiko 回环覆盖两轮成功、SFTP 复用、错误响应、取消清理和既有故障分类；真实服务器及多 DPI/高对比度体验单列验收。详见[SSH 认证说明](../SSH-AUTHENTICATION.md)。
