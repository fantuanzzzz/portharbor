# ADR 0009：本地诊断日志与可审阅导出

日期：2026-10-27；状态：已采纳。

## 背景

状态栏能显示错误，但关闭页面后缺少可关联的阶段、耗时和计数。任意异常消息和堆栈可能携带主机、路径或秘密，不适合直接写入或打包。

## 决策

Application 定义 `IDiagnosticLog`、安全事件 DTO、诊断包预览与导出。Infrastructure 实现本地 JSONL；UI 组合根接入终端、文件、RDP 和后台关闭失败。仅保存强类型允许字段，不序列化 `ConnectionDiagnostic.Message`、异常对象或配置文件。默认排除所有端点，比按主机字符串脱敏更保守；不提供取消脱敏的设置。

默认启用，单文件约 1 MiB 轮转、归档保留 14 天且最多 8 个；设置可持久化。一次记录可能使文件超过阈值，下一次写入前轮转。日志失败保留最多 500 条内存事件并标记失败，不让日志故障中断连接。没有后台写入队列，单次记录自行关闭文件句柄。

帮助菜单先展示最多 500 条事件的固定 JSON 快照，再经 `IFilePicker` 选择本地保存；保存内容必须等于预览，不自动收集配置、目录、终端文本或上传。远端提交不确定时仅记录恢复状态枚举，不能把尽力清理当作目标已恢复。

## 选项与影响

暂不引入日志框架依赖或在线收集。保留自有窄端口，未来可以替换存储实现。明确不采集原始异常类型名、消息和内部堆栈：牺牲部分调试细节，避免通过日志泄露路径/端点；如需更详细诊断，应先设计结构化安全字段和回归。

设置/日志位于配置目录下 `logs/`，便携模式随程序目录移动。日志上限、轮转、禁用、写入失败、敏感字段排除及预览/导出一致性由核心检查覆盖。

## 复审条件

高频记录造成 UI 延迟、需要跨进程写入或增加诊断字段时，重新审查队列、锁和数据最小化规则；禁止直接扩大为原始日志/配置打包。
