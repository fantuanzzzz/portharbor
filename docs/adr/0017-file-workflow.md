# ADR 0017：文件视图目录身份与最终操作结果

- 日期：2026-10-29
- 状态：已采纳

## 背景

原 FileView 没有排序和空状态，按钮始终可用；路径框草稿同时作为文件修改的目标目录，失败/进度/成功消息可能互相覆盖。P07 需要让日常文件操作可理解，同时保留现有单连接、单任务、超时、覆盖和目标保护策略。

## 决策

- FileView 区分路径草稿与最近成功加载目录。列表、上传及新建/重命名目标均属于已确认目录；仅导航读取成功才能切换目录身份。失败清空过期列表，不允许在未知目录状态下修改文件。
- 列排序由现有 RemoteEntry 元数据生成，目录始终在前，选择通过远程路径保留；成功空列表与失败状态分开展示。操作启用取决于忙碌、关闭、成功列表和选择类型，不能只依靠点击后的空返回。
- UI 接收现有诊断但保留最终结果的显示所有权。协议错误仍送到原诊断订阅者，只使用稳定呈现字段；取消/失败提示明确核对结果，成功操作后的刷新失败不宣称修改回滚。
- 进度只显示本次累计字节、真实已知总量及平均速率；未知总量不使用目录中的大小补齐。回调按操作编号和忙碌状态过滤，取消/结束后不覆盖最终结果，不新增百分比或剩余时间估计。
- 复用现有单任务、文件选择、覆盖/删除确认及可等待关闭流程，不新增队列、存储、协议接口或依赖包。

## 代价与验证

失败后需显式刷新才能恢复修改操作，路径输入草稿不会立即影响当前目录。此策略避免误写目标，但不提供跨客户端的远端事务保证。

通过真实 FileConnection 与内存文件系统的 UI 检查验证排序/选择、目录失败恢复、取消时本地旧文件保护、协议确认、进度乱序和路径草稿；已有共享传输契约及完整 UI 保持回归。真实服务器和多 DPI 体验单列验收，见[文件视图说明](../FILE-WORKFLOW.md)。
