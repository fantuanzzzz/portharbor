# ADR 0021：标准测试、配置写入所有权与构建追溯

- 状态：接受
- 日期：2026-10-30

## 背景

技术方案仍有 T6 测试迁移欠项；进程内配置锁无法防止两个应用实例读取不同快照后覆盖保存。发布和诊断缺少源码身份，RDP 客户端启动后程序崩溃会留下临时配置。

## 决策

1. 使用独立 net8.0 NUnit 4 项目调用共享纯逻辑检查，按稳定测试名称由 `dotnet test` 发现，输出 TRX。coverlet 只测量 Domain/Application。旧 Windows/协议/UI/ConPTY 检查保留其独立 JSON/截图证据，不以标准测试组数冒充断言覆盖数。
2. 应用入口在加载 Store/偏好/活动记录前取得配置目录 `.portharbor.lock` 独占文件句柄，持有到退出，OS 在崩溃后自动释放。不删除空锁文件，不通过“文件存在”判断占用。不同数据目录可并行；直接调用存储 API 的其他工具需自己持有同目录 lease。
3. `.editorconfig` 及 .NET 8 分析器/警告即错误适用于构建；格式检查增量执行到变更文件。旧源码随着后续修改规范化，不做与功能无关的全仓重排。
4. 发布时记录真实 Git commit、dirty 状态、源码文件内容摘要、SDK、runtime pack、依赖锁摘要及验证结果；同样的安全构建身份写入程序集并进入 schema 2 诊断包。缺失字段保留 null，未提交构建不冒充可凭 commit 复现的正式构建。
5. RDP 使用独立 GUID 工作区和 owner 文件/独占锁。owner 在启动前标记 launching，启动后记录 PID 与 UTC 启动时间；崩溃后仅清理无活跃 owner、能证明无客户端且仅有约定文件的目录。检查重解析点，删除只列出已知文件，不递归清理。启动/身份记录之间的空窗、未知文件和不可验证身份保守保留；不杀外部 mstsc，不清理旧根目录任意 `.rdp`。
6. CI 为已独立 net8.0 的纯核心增加 Linux/macOS 测试矩阵，与 Windows 验收通过后单独执行 P10 安装器验证；真实环境仍以 E01–E12 记录，不能用回环、模拟升级或 GitHub runner 代签收。新矩阵和 job 待推送执行，本机 Windows 不能代签其他 runner。

## 影响与限制

同目录多窗口改为明确拒绝，避免跨进程丢更新；该策略不回溯约束尚无 lease 的旧版进程，升级须先退出旧版。文件系统必须支持独占共享语义；网络共享/同步盘数据不作为已验收部署方式。空锁文件和 RDP owner 文件为内部状态，不是新增用户设置。

NUnit、adapter、Test SDK、coverlet 只在测试项目中恢复，不增加最终 EXE 的运行依赖。标准纯逻辑可以跨平台运行；本轮没有新增或承诺非 Windows UI 支持。

源码摘要按 Git 跟踪/未忽略的源文件字节计算，包含换行等实际内容差异；不是确定性 EXE 字节一致的承诺。Windows/Desktop runtime 来自 SDK 解析的固定 pack 版本，后续升级仍需同步第三方许可与重新验收。

真实硬件、服务器、Windows 账户/干净快照及旧版安装包缺失时记录阻塞原因。暂未启动的阶段 4 需要用户另行明确新平台/新 UI 目标，不自动扩展本轮范围。
