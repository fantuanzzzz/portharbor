# ADR 0015：会话编辑草稿、明确提交意图与字段校验

- 日期：2026-10-28
- 状态：已采纳

## 背景

原编辑器通过“保存此会话”复选框改变连接按钮含义，输入错误只在提交时弹窗；切换协议重置端口。现有密码库未解锁时，编辑流程还可能用空密码覆盖原凭据。P05 要改善这些操作，同时保留存储、平台能力和主机信任边界。

## 决策

- 编辑器持有独立草稿，仅在合法提交后发布结果。提供“仅连接 / 仅保存 / 保存并连接”和取消，分别返回明确的保存/连接意图；主窗口仍负责保存、主密码及连接顺序。取消不修改原会话。
- 当前协议区分基础与可展开高级字段，切换不清空文本、选项或秘密；端口按协议保留本窗口草稿，持久格式仍是原 `Session`。不引入编辑器偏好文件。
- Domain 返回字段键与稳定消息列表，原有 `Validate()` 从同一列表抛出第一项；UI 负责展示、即时清除和定位。分类使用现有 Application 路径规则，控件范围和原生交互留在界面。
- 两个连接动作共同遵守平台能力及点击时复查，仅保存可用于暂不可用的能力。编辑现有已保存凭据前先解锁，取消中止；不通过改变底层“空密码清除”规则解决 UI 未读取密码的问题。
- 密码默认隐藏，显式显示后在失去激活/切到不使用密码的协议时恢复隐藏，不保存显示状态。
- 文件选择复用原端口；目录选择以独立 `IFolderPicker` 表达，避免扩充所有 `IFilePicker` 使用者。`WindowsFilePicker` 实现两端口，目录选择使用独立的 `FolderBrowserDialog`、编辑器 owner 和每次释放，不创建目录。Application 不引用 WinForms，既有 Windows 平台项目仍不引用 WinForms。

## 代价与验证

编辑锁定凭据的会话需要先解锁；无法解锁时仍可从其他入口使用本次密码连接，但本轮不提供保留未知密码的编辑草稿操作。每协议端口草稿不是持久模板，重启后只保留上次实际保存的单一协议配置。

通过共享规则、真实 JSON/INI 原有兼容回归、原生适配器资源释放、编辑器及主窗口交互检查验收。选择器测试不点击系统对话框，注入终端不证明真实服务器认证成功；真实系统 DPI/高对比度体验单列。操作及限制见[编辑器说明](../SESSION-EDITOR.md)。
