# 0007：会话配置导入导出策略与原子存储边界

日期：2026-10-27；状态：已实施，当前工作区待提交。

## 背景

`ConfigurationService` 曾把路径直接转交给 Store，Store 分配导入 ID、合并分类，格式存储负责清除导出会话的 SavePassword。业务规则因此需要 Windows 存储才能测试。逐条调用会话保存用例会破坏原有整次导入的单次保存、失败回滚和并发语义。

## 决策

- Application 新增 `SessionConfiguration`，仅含分类和会话，不含密码库、凭据、主机信任或存储 schema。Session 是可变记录，端口实现与用例都复制会话，避免快照修改泄漏到活动状态。
- `IConfigurationTransfer` 定义读入文件、写出文件、读取一致快照及原子更新快照四个操作。更新接受纯转换回调；存储在共享锁内提供最新快照、计算结果并保存一次，保存失败恢复原集合。回调不得进行 I/O、用户交互或嵌套存储操作。
- `ConfigurationTransferService` 承担分类按不区分大小写去重且保持顺序、保留现有会话、为导入会话分配新 ID，以及导入/导出会话关闭 SavePassword 的规则。新 ID 不复用现有或导入源 ID；重复导入仍新增独立会话，不改为覆盖或按主机去重。
- `ConfigurationService` 调用该用例。Store 保留公开 Import/Export 兼容入口并委托同一用例，不再持有合并、ID 分配或清除 SavePassword 的算法。
- Store 格式适配器继续校验和读取 JSON v1/v2、INI，向应用层只返回可传输字段；输出保持原有 JSON v2 外形，密码库为 null、凭据和主机信任为空。输入 schema 校验仍在格式适配器；未修改迁移和加密方案。
- 整个导入在共享锁内基于最新数据合并，替换分类与会话后单次原子保存，异常时恢复旧集合。现有密码、密码库及信任集合不参与传输更新；不通过逐条 Save 循环拼装导入。

## 验证

独立 Application 检查使用内存端口，覆盖重复导入、空分类、ID 冲突、所有协议、快照隔离、读写失败及提交前更新。Windows 核心检查使用真实安装 JSON 与便携 INI，交叉导入 JSON v1/v2 和 INI，验证源文件保留、无效配置拒绝、保存失败回滚、并发合并、原子备份和重启后凭据关联。原有标为 INI 的存储检查实际使用 JSON 模式，本轮修正为真正便携 INI。

## 限制与复审

共享锁仅解决进程内并发，不提供跨进程事务。读取/写出文件仍为同步操作；导出继续使用原有 JSON 写出行为，不新增导出文件备份或损坏目标自动恢复承诺。UI 继续负责导入信任确认与选取路径。

引入导入预览、重复会话合并、冲突处理、其他输出格式、异步大文件导入、跨进程写入或 schema 变化时复审。不得把凭据或主机信任重新加入传输 DTO；不得在保存失败后返回成功数量。
