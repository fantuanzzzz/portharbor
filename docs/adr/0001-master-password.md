# 0001：主密码保护现有 Windows 密码库

日期：2026-10-23

状态：已采用

## 背景与选项

原配置 schema v1 使用 Windows 用户级 DPAPI 加密密码，同一 Windows 用户下无需额外口令即可读取。用户要求保存密码时必须设置主密码。

仅增加启动口令弹窗不能加强磁盘上密码的保护；单独替换成主密码加密会取消现有 Windows 用户绑定。因此选择在 DPAPI 密文外再加一层主密码加密。

## 决策

- schema v2 增加独立 `Groups` 分类列表和 `Vault` 元数据；仍读取 v1，设置主密码时迁移凭据并升级至 v2。
- 主密码至少 8 个字符，不做裁剪，不持久化；使用 PBKDF2-HMAC-SHA256、600,000 次迭代、32 字节随机盐派生 32 字节密钥。
- 使用 AES-256-GCM，每次加密生成独立的 12 字节 nonce，使用 16 字节认证标签；凭据 ID 作为附加认证数据，防止跨会话替换密文。
- 元数据包含格式版本、盐及使用独立认证上下文加密的固定校验值；磁盘不保存派生密钥。算法参数由密码库格式版本确定，后续改变参数需升级该版本。
- DPAPI 密文作为 AES 明文，保持 Windows 用户绑定。认证成功后才保留解锁密钥，退出时清除密钥缓冲区；托管字符串及第三方协议客户端持有的认证数据无法保证全部立即擦除。
- 启动时若存在密码库可输入主密码解锁，也可点击“跳过”进入软件；旧配置存在凭据时需设置主密码。首次保存非空密码前设置主密码，修改时在 UI 验证当前主密码并重新加密全部凭据。
- 旧凭据迁移先检查 DPAPI 可解密性，全部转换后再原子保存；失败恢复内存数据及旧密钥。导出只包含无密码会话及分类。

## 影响与限制

- v2 配置拒绝缺失密码库元数据却带有凭据的数据；旧版程序不能读取 v2，应备份原配置后升级。
- 保留现有原子写入与 `.bak` 行为。旧备份不会自动重新加密，可能继续使用旧主密码或仅 DPAPI；修改主密码不撤销既有副本的访问能力。
- 忘记主密码没有找回途径。会话元数据不加密；本次不增加自动锁定、密码找回、凭据跨设备迁移或安装/便携数据模式。
- 未新增依赖，使用 .NET 自带密码算法；主密码保护不能抵御已控制当前进程或当前 Windows 用户的恶意程序。

## 验证与复审条件

检查覆盖错误口令、重启锁定、修改口令保留凭据、密文篡改与跨会话替换拒绝、v1 迁移、写入失败回滚和无密码导出。

需要支持跨机器便携凭据、自动锁定、算法参数升级或标准密码库格式时复审本决策；不能通过移除 DPAPI 或默默降级来实现迁移。


## 2026-10-23 便携模式复审

用户明确要求安装版和便携版，便携配置保存到程序旁 INI。保留安装版密码库版本 1 的 DPAPI + 主密码保护；新增便携密码库版本 2，以主密码派生密钥直接 AES-256-GCM 加密凭据。新模式显式由便携包标记或启动参数选择，安装版数据不会自动迁移或降级。PBKDF2 参数、随机 nonce、凭据 ID 认证上下文和密钥清除方式不变。

更改主密码时先根据旧密码库版本解密，再根据当前运行模式重新加密；失败回滚。两种密码库版本独立于配置 schema v2。便携版 INI 复制后重启解锁及凭据明文的 AES 包络检查已覆盖；尚未在第二台真实 Windows 机器上实测。之前关于“不包含便携模式”的限制仅适用于本记录初版。
