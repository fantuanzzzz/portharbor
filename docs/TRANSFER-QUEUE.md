# P08 多文件传输队列

日期：2026-10-29。适用于 FTP/SFTP 文件标签，沿用[单文件传输契约](FILE-TRANSFER.md)。

## 使用方式

在成功加载目录后点击「批量上传」，通过系统选择器选择多个本地文件；目标固定为加入任务时的已确认远程目录。批量下载使用远程列表的 Ctrl/Shift 多选，再点击「批量下载」选择一个已存在的本地目录。目录不参与批量下载；多选时单文件下载、重命名和删除禁用。取消选择器不会创建任务或传输文件。

任务加入后显示底部列表，包括方向、文件、目标、状态及结果。加入任务不会立即传输，点击「开始 / 继续队列」才执行。每个文件标签严格按照加入顺序串行处理，最多保留 500 项（包括已结束任务）；不同标签拥有各自队列。执行期间暂停目录导航、单文件操作和继续添加任务。

任务状态为待开始、传输中、成功、失败、取消。当前任务显示累计字节、已知总量或未知大小；成功必须等协议和目标提交确认，进度到末尾不代表完成。目标存在时逐项询问覆盖，默认不覆盖；拒绝后该项取消，继续下一等待项。没有全局覆盖开关。

## 失败、取消与关闭

失败暂停后续等待项，已成功项保留且不重放。核对目标、暂存和备份结果后，可点击继续，只执行等待项；失败项本身需选中并点击「核对后重试所选…」，确认后返回待开始，仍需显式开始。取消项也可按此流程重新加入执行。原异常文字不写入任务结果。

「取消当前」取消当前文件并等待清理，然后允许其余等待项继续；「取消所选等待」只取消选中的未开始项，「取消全部等待」保留当前任务。若希望停止整批，先取消全部等待，再取消当前。顶部原「取消」取消本轮操作及全部等待项。任务已提交并得到成功确认后，迟到的取消不能将成功改写成取消。

关闭文件标签或应用会取消当前及等待任务，等待在途文件操作和连接释放；清理完成前不开始下一个文件。「清理已结束」只移除列表记录，不删除传输文件。队列仅在当前标签内存中存在，不持久化、不在重启后自动恢复。

失败和取消不能保证远端原路径保留旧文件，尤其是 SFTP 覆盖提交确认丢失。必须刷新或用新连接核对目标、`.part` 和 `.bak`，不能仅凭队列失败状态再次覆盖。队列没有绕过底层超时、恢复及清理语义，也没有自动重试。

## 文件名与范围

批量下载将远程名称中的 Windows 非法字符替换为下划线；清理后同名（不区分大小写）、保留设备名、尾随点/空格及无效路径会拒绝整批加入。此时可使用单文件下载另选名称。不同批次指向同一目标仍按顺序执行并逐项询问覆盖；不存在跨客户端目标锁。

首版不含目录递归、文件夹同步、断点续传、并行传输、拖拽排序或自动恢复。上传成功后的目录刷新失败会单独显示核对提示，不能据此把已确认成功的文件改写成传输失败。

## 实现与验收

`PortHarbor.Application/TransferQueue.cs` 管理状态与串行执行；`FileView.Queue.cs` 负责选择、覆盖确认、任务展示和原 `IFileTransfer` 接线。`IMultiFilePicker` 由独立 Windows Forms 适配器实现，Application 无 UI/厂商依赖；没有增加配置文件、schema 或依赖包。进度更新统一回到界面线程，并按操作编号和当前任务状态拦截迟到消息。

```powershell
dotnet run --project tests/PortHarbor.Checks -c Release --no-build -- --ui-queue artifacts/transfer-queue --results artifacts/transfer-queue/queue-ui-results.json
```

规则专项 14 项在两个检查项目共享执行，队列 UI 专项 23 项包含在完整 UI 回归中；系统多文件选择器增加 4 项适配检查。使用真实 FileConnection 与内存文件系统覆盖暂停/继续、显式重试、拒绝覆盖、序列化、名称冲突、取消与关闭；报告及运行数量见[开发日志](DEVELOPMENT-LOG.md)。截图在 ignored `artifacts/transfer-queue/queue-dark.png` 和 `queue-running.png`。真实服务器断线、原生对话框人工操作、多 DPI 和高对比度仍待环境验收；本轮没有重跑完整发行或协议回环。决定见 [ADR 0018](adr/0018-transfer-queue.md)。
