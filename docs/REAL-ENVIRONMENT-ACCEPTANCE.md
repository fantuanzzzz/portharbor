# 真实环境验收手册

登记日期：2026-10-30。以下 **E01–E12 均待真实环境执行**；本机替身、回环、模拟版本和截图规则检查不能将其勾为通过。执行后附环境、复现步骤和证据，再更新技术方案/产品进度。

## 准备与记录

使用测试 Windows 账户、可回滚虚拟机或专用设备，不在日常远程连接中测试断网/卸载。备份完整数据目录：便携为 EXE 旁整个使用目录；安装模式为 `%LOCALAPPDATA%\PortHarbor`。配置和密码库可能关联，不能只备份会话导出 JSON。测试使用临时账户、空目录与合成文件，关闭会话后做文件哈希。

发行产物来自 `build.ps1 -P10`；将 portable EXE、setup EXE、`release-manifest.json` 复制到测试机。检查 SHA-256 与清单的 Files 对应。记录清单中的 Commit、Dirty、SourceSnapshotSha256、SDK/runtime；Dirty 为 true 表示包含未提交修改，不能仅凭 commit 复现。干净 Windows 测试机不需要 SDK。

以下命令在**测试机** PowerShell 使用，路径可调整；新建目录应专用于本轮，不指向现有 PortHarbor 数据：

```powershell
$acceptanceRoot = 'C:\PH-Acceptance'
New-Item -ItemType Directory -Force $acceptanceRoot | Out-Null
$portable = Join-Path $acceptanceRoot 'PortHarbor-0.2.0-portable-win-x64.exe'
# 先将发布 EXE 和 manifest 复制到该目录，再执行下面的校验与运行命令。
Get-FileHash -LiteralPath $portable -Algorithm SHA256
# --portable 显式控制测试格式。
& $portable --portable --data-dir 'C:\PH-Acceptance\portable-data'
```

每次测试至少记录：编号、日期、测试人、Windows 版本/体系结构、显示器/DPI、设备/服务器及版本、二进制 SHA-256、构建身份、前提、实际步骤、预期/实际、耗时、通过/失败/阻塞、证据路径。截图和日志不得包含密码、私钥、挑战响应、终端秘密或实际业务文件；帮助菜单导出诊断前核对预览。不将完整配置/密码库上传 GitHub。

## E01：无 .NET 的干净 Windows 离线运行 / P10

环境：未安装 .NET Desktop Runtime/SDK 的 x64 Windows VM 或第二台机器，覆盖产品声明的 Windows 10 1809+ 与 Windows 11 代表版本。若使用 Windows Sandbox，记录其 Windows 版本，不能代表所有系统版本。

1. 在干净快照检查“已安装的应用”中无 .NET Desktop Runtime；断开测试 VM 的外网，复制产物与清单。
2. 将便携 EXE 放到可写的中文/空格目录，**直接双击**，不放 marker/INI/启动脚本。创建并保存一条测试会话、偏好和主题，退出重启。
3. 确认程序旁生成 INI，数据/偏好保持，不要求安装 .NET；确认“帮助 → 第三方许可”离线可打开。
4. 运行安装向导，分别验证中文和英文，选择目录、桌面图标选项、取消安装，再完整安装。从开始菜单和桌面快捷方式启动，确认用户数据与程序目录分离。
5. 在专门的只读测试目录放便携 EXE 运行，应明确报告无法写入，不静默切换数据目录。恢复到可写目录后备份数据仍可读取。

预期：离线首次运行成功，使用后允许产生数据及 .NET 解包缓存；真实向导可操作。记录 SmartScreen/杀毒提示（当前未签名），不要把未签名造成的信誉提示误记为 .NET 缺失。证据：环境截图、EXE 哈希、首次/重启结果、许可页面及向导截图；失败时保留诊断和错误提示。

## E02：真实版本升级、卸载与旧配置迁移 / P10、阶段 0

环境：测试 Windows 用户，取得**真实上一发行版本**安装器和本次新版本。当前正式版本号为 0.2.0；流水线模拟 0.2.0→0.2.1 不等于历史版本升级。缺少历史包时将真实旧版升级标为阻塞并记录原因，先测同版重装和卸载。

1. 用旧版本创建分组、七协议测试会话、收藏/最近、偏好、信任记录，以及“保存密码”的测试凭据并设置主密码。正常退出，备份整个数据目录与文件哈希。
2. 在程序目录放 `user-owned.txt`，运行新安装器。确认沿用原安装目录及唯一的卸载/快捷方式入口，受管理程序文件被更新。
3. 新版本打开旧数据，核对 ID、分组、非默认字段、收藏/偏好及测试凭据可用；不将打开时合法的迁移误判为数据损坏。记录迁移前后差异。
4. 通过 Windows 设置卸载。确认 EXE、快捷方式、卸载登记移除，用户数据及 `user-owned.txt` 保留。重新安装再核对完整数据。
5. 将安装路径选择为测试便携目录或数据目录，验证安装器拒绝；不要以真实工作目录进行覆盖测试。

预期：不混用安装/便携数据，不删除未知文件，迁移失败保留旧配置/备份。证据：前后数据清单/哈希、字段核对记录、升级/卸载日志；密码仅记录“可用/不可用”。

## E03：混合 DPI、多屏、浅色/深色与高对比度 / P01–P09

环境：真实交互桌面；分别使用 100%、125%、150%、200% 缩放，有条件使用两台不同 DPI 显示器。记录分辨率、主屏、缩放和文字大小。

1. 两种主题分别打开主窗、会话编辑器、终端设置、文件视图/队列、诊断预览和 SSH 挑战对话框；检查文字完整、按钮可见、错误信息/焦点不只靠颜色。
2. 最大化、还原、缩窄窗口；拖到另一 DPI 显示器；退出，断开副屏，再启动。确认窗口可找回、侧栏和操作区可操作，不落在屏幕外。
3. 开启 Windows 系统高对比度，重复上述页面、选中/禁用/错误状态；程序运行期间切换，再退出高对比度，核对恢复。
4. 改终端字体和配色，主题切换不得覆盖终端偏好；中文、宽字符、滚动和查找定位正常。

预期：无遮挡、不可达控件或关键状态不可辨。证据：同页面各缩放/主题截图、混合 DPI 移动录像、系统设置截图；仅模拟屏幕几何或颜色映射不算实测。

## E04：纯键盘、原生对话框与系统剪贴板 / P01–P09

1. 不用鼠标，通过 Tab/Shift+Tab、F6/Shift+F6、Ctrl+Shift+F、Ctrl+Shift+B、会话树 Enter/F2 完成查找、编辑、连接；核对焦点可见和顺序。
2. 在编辑器触发多字段错误，核对首个错误可定位；Enter/ESC 的提交/取消与按钮文案一致，取消不保存草稿。
3. 真正操作私钥/Shell 文件选择器、多文件上传选择器和下载目录选择器，覆盖中文/空格路径、取消、覆盖拒绝；不只使用假选择器返回路径。
4. 将终端文本复制到记事本核对；尝试多行粘贴、取消确认、右键粘贴开关和左键复制开关。重连后旧命令不得自动重放。
5. 用实际服务器触发隐藏/可见 SSH challenge，核对隐藏输入、焦点、取消、关闭标签和关闭窗口。

预期：没有误执行、误保存、密码显示或响应进入日志；取消后 UI 可继续使用。证据：操作清单与脱敏截图/录屏，挑战内容只用测试值。

## E05：SSH/SFTP 认证、主机信任与服务器互通 / P05、P09、阶段 3

环境：专用 OpenSSH 服务器及至少一种实际目标服务器/网络设备，分别启用所需认证方式；管理员提供测试账号和可信指纹。

1. 分别验证密码、无口令私钥、带口令私钥、keyboard-interactive 多轮挑战；终端与 SFTP 都执行，不假定所有服务器支持每种方式。不支持的组合记录“不适用”及服务端配置依据。
2. 首次连接核对独立取得的指纹，分别拒绝/接受；在可回滚测试服务器更换主机密钥，确认拒绝变化并需明确处理信任，不能静默连接。
3. 输入错误密码/私钥口令/挑战响应，再取消挑战或关闭标签；检查线程和连接释放，新建连接仍可用。测试仅私钥模式不得意外回退密码。
4. 挑战窗口等待超过连接期限，再提交/取消：按当前设计等待由用户控制，15 秒期限仍计时，到期后提交/取消结束为超时；不期望自动关闭模态框。
5. SFTP 读写中文/空格目录，确认当前路径、权限拒绝、列表排序与文件内容；记录服务器系统、SSH 实现/版本和认证配置。

预期：认证规则符合[认证说明](SSH-AUTHENTICATION.md)，指纹变化可见，失败不泄密。证据：认证矩阵、OperationId、脱敏诊断与测试服务器日志。

## E06：FTP / 显式 FTPS 与多种服务器 / P07–P08、阶段 3

环境：实际 FTP 和支持显式 TLS 的测试服务器、可核验的有效证书和独立无效证书测试端点；测试账号限制到空目录。

1. 验证被动 FTP 的列目录、新建目录、重命名、上传、下载、删除文件/空目录；不要求递归操作。普通 FTP 仅用可丢弃凭据与隔离网络。
2. 勾选 TLS 连接有效证书的显式 FTPS，检查数据通道传输；连接过期/不受信任/名称不匹配证书应失败，不增加“忽略证书”开关。
3. 测试中文路径、空目录、大文件、只读目录及服务端配额限制；上传和下载后比较 SHA-256。
4. 用 Ctrl/Shift 选择多个文件，加入队列后逐项确认覆盖；拒绝一项、失败一项、取消当前/等待任务，再核对目标后显式继续。

预期：列表和进度不报虚假成功，失败暂停，不自动重放，未知提交先核对。证据：服务器/证书版本、测试文件哈希、队列结果、脱敏服务端日志。

## E07：物理断网、黑洞、服务端异常与未知提交 / 阶段 1、P06–P08

环境：专用客户端/VM 和测试服务器；准备可随时恢复的网络连接与服务器控制台。黑洞由测试网络/VM 规则丢弃该测试连接的数据包，不影响管理链路；不要在工作主机直接禁用全部网络或防火墙。

1. 分别在 DNS、握手、认证、目录列表、上传/下载阶段切断专用网线/测试 VM 网卡，记录开始、错误、取消、关闭标签的时间；恢复网络后**显式**重连。
2. 黑洞测试只丢弃数据包而不发送 TCP reset；分别观察自然超时和主动取消。恢复后重连应可用，不把旧实例后台延迟结果写入新页面。
3. 在隔离服务器停止服务、重启或撤销目录权限；核对错误类别、阶段和 OperationId，UI 应保持响应，不把所有失败统一当密码错误。
4. 使用较大合成文件，在 SFTP 覆盖目标的提交/备份恢复窗口断开链路；核对目标、`.part`、`.bak` 的实际内容/哈希。时序无法稳定命中则记录“未命中”，不算通过。
5. 队列失败后应暂停；先在新连接核对远端，再手动恢复备份或重排失败项。未经核对不点继续，不自动删除未知状态的备份。

预期：无永久阻塞或误报提交成功；记录实测时长及配置期限，区分连接/操作/恢复阶段。当前 UI 文件连接期限 15 秒，单次文件操作整个期限 30 秒（并非无进度才计时），恢复/清理另限时 5 秒；慢速大文件超过操作期限也会超时，应单独记录。取消成功不承诺撤销已在服务端完成的提交。证据：时间线、双方日志、目标/暂存/备份哈希，恢复后再次连接结果。

## E08：真实串口、阻塞与拔插 / 阶段 1、阶段 3

环境：受支持的 USB 串口适配器、驱动版本及专用回环/测试设备，按设备厂商说明连接，不在生产设备上随意短接引脚。记录 COM、波特率、数据位、校验、停止位、流控。

1. 枚举端口，按测试设备已知设置连接，双向发送可识别测试序列，确认顺序及中文/字节边界。
2. 用另一测试程序占用端口，连接应明确报错；释放后重新检查并连接。
3. 设备持续输出、停止读取/流控造成写阻塞时，分别取消/关闭标签/退出程序；设备拔出后再次关闭并重新插入。
4. 拔插后端口号可能变化，重新选择设备；用设备工具确认 PortHarbor 没有继续占用端口。

预期：可取消释放，不死锁，不把重新插入设备自动当旧连接继续发送。证据：适配器/驱动/固件、参数、关闭耗时、测试序列及端口复用结果。没有硬件/受控流控设备时此项只能保持待验收。

## E09：真实 RDP 登录、退出与遗留清理 / 阶段 3

环境：Windows mstsc 可用、允许 RDP 的测试远端和临时用户；本机回环替身只能证明启动参数/进程清理，不能证明登录成功。

1. 分别用默认/非默认端口，用户名、全屏、剪贴板选项连接；在远端核对实际登录及设置。凭据由 Windows 客户端处理，PortHarbor 的“已启动”不代表认证成功。
2. 正常关闭 mstsc 后检查数据目录 `rdp-temporary/<GUID>/connection.rdp` 被清理。
3. 启动连接后在任务管理器只结束这次测试 PortHarbor 的 PID，保持 mstsc 开启。重新启动 PortHarbor，当前仍在运行的客户端配置应保留；退出 mstsc 后重启或再发起 RDP，可清理可确认已结束的管理文件。
4. 强退时机若落在客户端启动与身份记录之间，目录会处于 `launching`，程序保守保留。归属未知、内容损坏、重解析点或多出用户文件也不自动删除。

预期：不终止用户的 mstsc，不扫描/删除其他 `.rdp`。历史根目录 `rdp-*.rdp` 不做通配清理；确认所有相关客户端退出、核对文件来源并备份后，可人工删除确认由程序生成的文件。证据：远端登录记录、客户端退出时间、管理目录前后清单；不要上传含真实主机/用户信息的 `.rdp`。

## E10：DPAPI、账户隔离及便携密码库 / 阶段 3、P10

1. 安装模式在测试账户 A 设置主密码、保存测试凭据，退出重启，确认解锁和实际认证成功。
2. 复制完整安装数据到测试账户 B 或另一台 VM，使用同一主密码尝试解锁；Windows 用户级 DPAPI 应阻止读取，提示失败，文件哈希/备份保留，不降级保护或自动清空。
3. 对便携模式另建独立测试库，设置主密码、保存测试凭据，退出后将整个便携使用目录复制到另一台测试机，按便携规则验证解锁。
4. 分别测试错误主密码、跳过解锁和更改主密码后重启；跳过时不得使用未解锁的保存密码。会话导出不含密码，导入不携带密码库。

预期：安装模式密文不具跨账户可移植性，便携与安装数据不混用。证据只写“解锁/认证成功或失败”、哈希、测试账户标签，禁止保存实际密码/密文作公开附件。

## E11：第二台机器干净 checkout 与 FTP 550 追踪 / 阶段 0

环境：第二台 Windows、Git、PowerShell 7（pwsh）、.NET 8 SDK、Python 和网络。先提交/推送本批源码，使用清单记录的确切 commit；本轮 dirty 源码不是可直接 checkout 的发行提交。

```powershell
git clone <你的仓库地址> C:\PH-Acceptance\source
Set-Location C:\PH-Acceptance\source
git checkout <待验收提交号>
python -m pip install -r tests/requirements.txt
pwsh -File build.ps1 -ExtendedBaseline -OutputDirectory artifacts/clean-baseline
```

在新 clone、空项目缓存运行，不复制 `.packages`、`.build-home` 或既有 artifacts；保存 `engineering-baseline.json`、TRX、Cobertura、旧 JSON、fixture/stdout/stderr 和 UI/ConPTY 证据。如再次出现历史 Temp 路径 FTP 550，记录 fixture 根路径、当前远程目录、FTP 命令/回复时间、文件存在性、权限和服务端日志；单次重跑通过或换目录通过不能证明根因。脱敏日志不要包含认证内容。本项完成第二机复现，并另行给出 550 的可复现原因；不可确认时保留“原因未查明”。

## E12：配置多实例、崩溃恢复与数据保留 / 阶段 0、P10

1. 同一 EXE 对同一 `--data-dir` 启动两个窗口，再用 `..` 或大小写不同的等价路径重复。第二个启动应明确拒绝，已有窗口的数据不能被覆盖。
2. 将同一配置目录分别以安装/便携模式指向，仍只能有一个写入者；使用不同 `--data-dir` 可同时运行。安装副本和便携副本共用数据目录也受保护。
3. 在专用测试进程已保存配置并空闲后，通过任务管理器结束其 PID；重启应能取得目录锁并读回完整配置。不要在工作配置中故意强杀写入。
4. 目录留下空 `.portharbor.lock` 是正常现象；它是否存在不代表被占用，退出/崩溃后无需手动删除。占用期间不能删锁文件绕过保护。

预期：基于操作系统文件句柄的独占、退出/崩溃自动释放。该策略覆盖应用入口；直接调用 Store 的工具需自己持有同目录 lease。证据：启动参数、提示、测试 PID、重启前后配置哈希。
