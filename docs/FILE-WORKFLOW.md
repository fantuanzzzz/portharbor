# P07 文件视图工作流

日期：2026-10-29。适用于 FTP/SFTP 文件操作界面。P08 批量传输与任务管理见[多文件传输队列](TRANSFER-QUEUE.md)。

## 路径与列表

路径框支持输入后按 Enter 或「前往」，双击目录进入，「上级」返回最近成功加载目录的父级，根目录禁用上级。刷新重新读取路径框中的目录；只有读取成功，才将其作为新的已确认目录。输入路径草稿不会改变现有列表所属目录，上传、新建目录和重命名始终基于已确认目录。导航失败清空过期条目并禁用文件修改，显示重试提示。

点击名称、类型、字节或修改时间表头切换排序，活动列显示方向箭头。目录始终排在文件前，大小按数字、时间按实际值排序；重新排序按远程路径保留当前选择。缺少修改时间或负数大小显示“未知”。没有选择时下载、重命名和删除禁用；选中目录时下载禁用。首次成功读取前上传和新建目录禁用。

成功的空目录显示“目录为空”；目录读取失败显示“目录未能加载”并保留刷新入口，两者不会混淆。错误在底部就地显示操作名称、稳定诊断与操作编号（若有），不显示原异常中的端点/私人路径，也不再额外弹出通用失败窗口。覆盖、删除和无效名称仍保留原确认/校验。

## 传输与取消

当前视图一次执行一个操作。处理期间禁用导航和文件修改，保留「取消」；点击后显示等待操作和清理完成的提示。操作结束前不开放后续任务；关闭标签和应用退出仍先等待取消与释放。

上传/下载显示累计字节、已知总量或“未知大小”，以及本次传输耗时计算的平均速率。总量以传输层回调为准，不拿列表大小冒充可靠总量，不显示虚构百分比；流复制到末尾仍需等待协议/目标提交确认。速度是平均值，不是瞬时带宽或剩余时间估计。

最终结果显示上传/下载/新建目录/重命名/删除已完成；拒绝覆盖明确显示未上传。进度回调带本次操作标识，已结束、正在取消或来自旧操作的进度不会覆盖最终状态。若修改已执行但随后的目录刷新失败，界面报告失败并要求刷新核对，不声称修改已回滚。

取消/失败时提示刷新并核对结果。下载临时文件、上传 `.part`、SFTP `.bak` 恢复与确认丢失继续遵守[传输契约](FILE-TRANSFER.md)，不能把取消提示理解为远程旧目标始终保留。P08 在这些边界上增加串行队列；多选时保留批量下载入口，单文件下载、重命名及删除禁用。没有自动重试、断点续传或递归目录传输。

## 验证与范围

专项入口（先完成 Release 构建，在可交互 Windows 桌面执行）：

```powershell
dotnet run --project tests/PortHarbor.Checks -c Release --no-build -- --ui-files artifacts/file-workflow --results artifacts/file-workflow/files-ui-results.json
```

规则和存储格式未增加新文件或 schema；界面消费现有 `IFileTransfer` 和结构化进度。专项使用真实 `FileConnection` 与内存文件系统，覆盖列表排序、选中项、空目录/失败恢复、未知进度、取消等待协议确认时保护旧本地目标、成功确认、延迟进度及路径草稿隔离。截图为 ignored `artifacts/file-workflow/files-list.png`、`files-empty.png`、`files-progress-dark.png`；最终数量见[开发日志](DEVELOPMENT-LOG.md)。

真实 FTP/FTPS/SFTP 服务器、设备、多 DPI、高对比度和原生文件选择对话框仍按技术方案的环境专项验收；禁用列表及原生表头空白区域可能使用 Windows 外观。决定见 [ADR 0017](adr/0017-file-workflow.md)。
